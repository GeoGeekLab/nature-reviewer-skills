# CRD-v1 three-domain pilot — preregistration

## Status

This document freezes the pilot design **before model inference**.

The pilot evaluates whether adding the corresponding Nature Reviewer Skill changes controlled scientific issue detection relative to a frozen generic scientific-review prompt while holding the base model and inference settings fixed.

This is a feasibility and diagnostic experiment. It is not powered or designed to establish expert equivalence.

## Study subset

The pilot includes every CRD-v1 case from:

- remote sensing;
- chemistry; and
- engineering.

That gives:

- 18 excerpts;
- 9 matched positive/control pairs;
- 3 pairs per domain;
- 3 independent model runs per excerpt per condition;
- 54 outputs per condition;
- 108 raw model outputs in total.

Case selection is rule based, not outcome based. No case is removed after inference because it appears difficult, ambiguous, or unfavorable.

## Conditions

### A — generic

The tested model receives:

1. the frozen generic-review prompt; and
2. the manuscript excerpt.

It does not receive any reviewer skill.

### B — skill-assisted

The same tested model receives:

1. the frozen skill-assisted prompt;
2. the manuscript excerpt; and
3. the corresponding domain skill package.

No other setting is intentionally changed.

## Model and inference settings

The exact model/version must be supplied to the packet-preparation script **before the first inference call** and recorded in the generated run manifest.

The following must then remain fixed across both conditions:

- model/version;
- temperature, top-p, seed, or equivalent controls when exposed;
- maximum output policy;
- system-level safety/tool policy;
- web access;
- external retrieval;
- execution environment.

The pilot freezes web and external retrieval as **off** so the comparison isolates the skill package rather than search behavior.

If the runtime does not expose a parameter, record it as unavailable rather than inventing a value.

## Blinding

The tested model must not receive:

- case_id;
- pair_id;
- case_type;
- challenge;
- target_issue_id;
- source_keys;
- gold_concerns;
- oracle predictions;
- the matched counterpart.

The execution packets generated by `scripts/prepare_blinded_pilot.py` contain only an opaque blind ID, frozen prompt, manuscript excerpt, and—only for the skill-assisted arm—the skill path required by the execution harness.

Annotators must be blinded to condition and case type during initial coding.

## Repeated runs

Each excerpt is run three times in each condition.

Repeated runs are **not treated as independent manuscript cases**. They are nested within the same case and pair. Bootstrap uncertainty is therefore resampled at the matched `pair_id` level, retaining all repeated runs inside each sampled pair.

## Primary endpoints

1. **Essential-issue recall**  
   Mean target-issue detection rate across positive cases, first averaging repeated runs within each case.

2. **Target specificity**  
   Mean probability that the paired target issue is *not* raised on the repaired negative control, first averaging repeated runs within each case.

3. **Essential balanced accuracy**  
   Mean of essential-issue recall and target specificity.

4. **Paired-pass rate**  
   Fraction of pair/run combinations in which the positive member triggers the target issue and the corresponding control does not.

The comparison effect is reported as:

`skill-assisted − generic`

for each endpoint.

## Secondary endpoints

- micro precision;
- micro recall;
- micro F1.

These use adjudicated codebook-matched concerns. Unrelated coded concerns remain false positives even when they do not cause the target-specific control endpoint to fail.

## Uncertainty

Use 10,000 non-parametric bootstrap draws over the 9 matched pair clusters.

Each sampled pair carries:

- positive and control cases;
- all three repeated runs;
- both experimental conditions.

This preserves the experimental dependence structure.

Report percentile 95% confidence intervals for each condition and for the paired condition difference.

Because there are only 9 pair clusters, intervals are descriptive and may be wide or discrete. Do not convert a pilot confidence interval into a general scientific-performance claim.

## Annotation

Raw model outputs are preserved unchanged before coding.

For results intended for public scientific interpretation:

- use at least two independent domain-competent annotators;
- blind them to condition and case type;
- calculate agreement before adjudication;
- adjudicate disagreements under the public codebook;
- retain pre-adjudication and adjudicated records.

The tested model must never emit benchmark issue IDs itself.

## Exclusions

No output is excluded for poor quality, verbosity, refusal, or failure to identify a concern.

A technical execution failure may be rerun only when no substantive model response was produced. The rerun reason must be recorded.

## Stopping rule

The pilot ends after the pre-specified 108 substantive outputs are collected. Do not add runs because a condition appears unstable or because a result is unfavorable.

## Interpretation boundary

Even a clear skill-assisted improvement would support only:

> improved performance on this public, skill-aligned, synthetic controlled diagnostic subset under the tested model and inference configuration.

It would not establish:

- superiority on arbitrary scientific manuscripts;
- expert-level reviewing;
- editorial-decision quality;
- novelty assessment;
- literature completeness;
- prospective publication outcomes.

An independently designed, access-controlled expert benchmark remains required for those claims.
